Prepare seu computador para o laboratório

Nosso projeto utiliza uma API em Node.js, TypeScript e Express, com banco de dados PostgreSQL executado pelo Docker. Para trabalhar no código, você também utilizará o Git e um editor de sua preferência.

Escolha abaixo o sistema operacional do computador em que pretende executar a aplicação. Abra cada etapa para encontrar o link oficial de instalação, os comandos de verificação e o que fazer depois.

Você não precisa instalar tudo de uma vez nem ler as instruções dos outros sistemas.

O que será necessário

Ferramenta Para que serve Necessidade
Node.js + npm Executar a API e instalar bibliotecas Necessário
Git Clonar o repositório privado e registrar alterações Necessário
Docker com Compose Executar o PostgreSQL em container Necessário para rodar localmente
VS Code ou outro editor Ler, editar e investigar o código Recomendado
REST Client, Postman ou Insomnia Enviar requisições HTTP Opcional

Não instale separadamente PostgreSQL, TypeScript, Prisma ou Express. O banco é executado pelo Docker e o script do projeto instala as dependências necessárias.

Sobre o Node.js: a API aceita versões a partir de 20.19.0. Para preparar um computador hoje, prefira a linha 24 LTS, desde que atenda aos requisitos de sua máquina. Versões antigas podem funcionar no laboratório mesmo após o fim do suporte de segurança, mas não são recomendadas para novas instalações.

Escolha seu sistema operacional

Windows Instalação pelo navegador, PowerShell e Docker Desktop. Pode exigir WSL 2 e virtualização. 5 etapas
1. Instalar Node.js e npm

O Node.js é o ambiente utilizado para executar nossa API. O npm, instalado junto com ele, é responsável por obter as bibliotecas do projeto.

  1. Acesse o site oficial de download do Node.js.
  2. Escolha a versão LTS compatível, preferencialmente a linha 24, e o instalador para Windows (.msi).
  3. Execute a instalação mantendo as opções padrão adequadas ao seu ambiente.
  4. Feche e reabra o PowerShell ou o terminal do Visual Studio Code.
  5. Execute:
PowerShell 
node -v
npm -v

Resultado esperado: os dois comandos mostram números de versão. Se o Node.js instalado for anterior a 20.19.0, atualize-o antes de executar o laboratório.

Não é necessário instalar npm separadamente, nem instalar TypeScript ou Prisma de modo global.

2. Instalar Git

O Git permitirá obter o código da equipe e enviar alterações ao repositório privado.

  1. Acesse Git para Windows.
  2. Baixe o instalador compatível com o computador e execute-o.
  3. Após concluir, abra um terminal novo e verifique:
PowerShell 
git --version

Resultado esperado: uma mensagem iniciada por git version.

O GitHub exige autenticação para acessar repositórios privados. O convite à equipe e o acesso ao repositório são explicados no guia de GitHub da disciplina. Não utilize sua senha da conta como senha de operações Git por HTTPS.

3. Instalar e iniciar Docker Desktop

O Docker executará o banco PostgreSQL em um container. Não é necessário instalar o PostgreSQL separadamente.

  1. Consulte a documentação oficial do Docker Desktop para Windows.
  2. Confira os requisitos de sistema, virtualização e WSL 2 informados na documentação.
  3. Instale o Docker Desktop e reinicie o computador se solicitado.
  4. Abra o Docker Desktop e aguarde a inicialização do Docker Engine.
  5. No PowerShell, execute:
PowerShell 
docker --version
docker compose version
docker info

Resultado esperado: os comandos mostram a versão do Docker, a versão do Compose e informações do Engine. O comando docker info não deve terminar com erro de conexão.

Se o instalador exigir WSL 2: siga a documentação do Docker. Em computadores pessoais compatíveis, a instalação pode exigir a configuração do WSL com permissões administrativas. Em computador institucional, não altere configurações de virtualização ou políticas de segurança sem autorização.

Importante: apenas ter o comando docker instalado não significa que o Docker Engine esteja rodando. Verifique docker info com o Docker Desktop aberto.

4. Preparar editor e ferramentas opcionais

Para ler e editar código, recomendamos o Visual Studio Code, mas você pode utilizar outro editor de sua preferência.

Se utilizar o VS Code, algumas extensões úteis são Prisma, ESLint, Prettier e REST Client. Elas não são exigidas para executar a API.

Para testar requisições HTTP, o projeto disponibiliza docs/requests.http, que pode ser usado com REST Client. Também é possível usar Postman ou Insomnia.

5. Conferir a instalação no Windows

Abra um PowerShell ou um terminal integrado novo e execute:

PowerShell 
node -v
npm -v
git --version
docker --version
docker compose version
docker info

Se todos responderem sem erro, avance para Depois de instalar: executar o laboratório, abaixo dos sistemas operacionais.

Se algum comando não for reconhecido, tente primeiro fechar e reabrir o terminal. Consulte a seção Problemas frequentes ao final desta página.

macOS Instalação adequada ao processador Apple Silicon ou Intel, Terminal e Docker Desktop. 5 etapas
1. Instalar Node.js e npm
  1. Acesse o download oficial do Node.js.
  2. Selecione uma versão LTS compatível, preferencialmente da linha 24, e o instalador adequado ao macOS.
  3. Conclua a instalação e abra uma nova janela do Terminal.
  4. Verifique:
Terminal 
node -v
npm -v

Resultado esperado: versões identificadas para Node.js e npm. A API aceita Node.js a partir de 20.19.0.

Se você utiliza um gerenciador de versões do Node.js, como nvm, confirme qual versão está efetivamente ativa na janela do terminal antes de executar o projeto.

2. Verificar ou instalar Git

Muitos Macs já possuem Git ou oferecem sua instalação por meio das ferramentas de linha de comando da Apple.

Execute:

Terminal 
git --version

Se o sistema solicitar as ferramentas de desenvolvimento, acompanhe a instalação oficial. Você também pode iniciar essa instalação com:

Terminal 
xcode-select --install

Outra alternativa é consultar as opções de instalação do Git no macOS, incluindo Homebrew e MacPorts.

Resultado esperado: git version ....

3. Instalar e iniciar Docker Desktop

O Docker será responsável pelo PostgreSQL utilizado no laboratório.

  1. Acesse a documentação oficial do Docker Desktop para Mac.
  2. Escolha o instalador adequado ao seu computador: Apple Silicon (chips da família M) ou Intel.
  3. Instale, abra o Docker Desktop e conclua as autorizações necessárias.
  4. Aguarde o Docker Engine iniciar.
  5. No Terminal, execute:
Terminal 
docker --version
docker compose version
docker info

Resultado esperado: o Docker e o Compose estão instalados e docker info consegue consultar o Engine.

Não há necessidade de instalar manualmente o PostgreSQL no macOS.

4. Preparar editor e ferramentas opcionais

Baixe o Visual Studio Code para macOS ou utilize um editor equivalente.

Se optar pelo VS Code, as extensões Prisma, ESLint, Prettier e REST Client podem auxiliar a análise. Também é possível testar a API com Postman ou Insomnia.

Essas ferramentas são opcionais e não precisam ser instaladas para executar os scripts do projeto.

5. Conferir a instalação no macOS

Em uma nova janela do Terminal, execute:

Terminal 
node -v
npm -v
git --version
docker --version
docker compose version
docker info

Se todos responderem sem erro, vá para Depois de instalar: executar o laboratório.

Se o terminal não encontrar um comando recém-instalado, reinicie a sessão do terminal ou consulte a seção Problemas frequentes.

Linux Orientações para Ubuntu e Debian, com links para outras distribuições; Docker Engine e Compose plugin. 5 etapas
1. Instalar Node.js e npm

A versão do Node.js disponibilizada pelo gerenciador de pacotes da sua distribuição pode ser antiga. Por isso, verifique sempre a versão instalada e prefira uma versão LTS com suporte.

  1. Acesse o site oficial do Node.js.
  2. Selecione um método apropriado à sua distribuição e arquitetura, preferencialmente para a linha 24 LTS.
  3. Conclua a instalação e execute:
Terminal 
node -v
npm -v

Resultado esperado: ambos os comandos exibem versões. A API exige pelo menos 20.19.0, mas uma linha LTS com suporte é preferível.

Não use sudo npm install -g para instalar Prisma, TypeScript ou Express. Essas dependências são específicas do projeto e serão instaladas pelo setup.

2. Instalar Git

Para Ubuntu e Debian, abra o terminal e execute:

Terminal 
sudo apt update
sudo apt install -y git

Depois confira:

Terminal 
git --version

Resultado esperado: git version ....

Se utilizar Fedora, Arch ou outra distribuição, consulte o guia oficial do Git para Linux e utilize o procedimento correspondente à sua distribuição.

3. Instalar Docker Engine e Compose plugin

No Linux, recomendamos o Docker Engine com o plugin Docker Compose v2. Não é necessário instalar o Docker Desktop.

  1. Identifique sua distribuição Linux.
  2. Siga o procedimento oficial completo da documentação do Docker, incluindo configuração do repositório e instalação dos componentes indicados.
  3. Certifique-se de instalar o Compose plugin, e não apenas a versão antiga docker-compose.

Documentação por distribuição:

  • Ubuntu: Instalar Docker Engine no Ubuntu.
  • Debian: Instalar Docker Engine no Debian.
  • Fedora: Instalar Docker Engine no Fedora.
  • Outras distribuições: Documentação geral do Docker Engine.
  • Compose: Instalar o plugin Docker Compose.

Em distribuições que utilizam systemd, você pode verificar o serviço com:

Terminal 
sudo systemctl status docker

Se a instalação foi concluída, mas o serviço está parado, pode ser necessário iniciá-lo:

Terminal 
sudo systemctl start docker

Depois teste com seu usuário habitual:

Terminal 
docker --version
docker compose version
docker info

Resultado esperado: os três comandos funcionam. O script npm run setup utiliza o comando docker sem sudo.

Se houver erro de permissão: consulte as orientações oficiais de pós-instalação do Docker no Linux. A participação no grupo docker concede privilégios elevados. Não altere permissões do socket Docker indiscriminadamente.

4. Preparar editor e ferramentas opcionais

O Visual Studio Code está disponível para diversas distribuições Linux. Outros editores podem ser utilizados.

Extensões recomendadas: Prisma, ESLint, Prettier e REST Client. Também é possível utilizar Postman ou Insomnia para testar endpoints.

O editor e essas extensões não fazem parte da instalação obrigatória da API.

5. Conferir a instalação no Linux

Em um novo terminal, com o usuário que executará o projeto, rode:

Terminal 
node -v
npm -v
git --version
docker --version
docker compose version
docker info

Resultado esperado: comandos reconhecidos e Docker Engine acessível pelo usuário sem erro de permissão.

Se algum deles falhar, consulte Problemas frequentes antes de iniciar o setup.

Depois de instalar: executar o laboratório

Esta sequência é igual em Windows, macOS e Linux. Não é necessário repetir a preparação completa a cada aula.

  1. Acesse o repositório da sua equipe

    O código será disponibilizado em repositórios privados da organização: github.com/appsec-labs-cesar-school.

    Você precisará receber e aceitar o convite correspondente à sua equipe. Ter o link da organização não significa ter acesso automático aos repositórios privados.

    Se ainda não conseguir acessar seu repositório, consulte o guia "Como acessar o GitHub" e verifique se o convite foi aceito.

  2. Clone o repositório

    No GitHub, abra o repositório da equipe, escolha Code → HTTPS e copie sua URL.

    No terminal, execute:

    Terminal 
    git clone URL_DO_REPOSITORIO_DA_EQUIPE
cd NOME_DA_PASTA_CLONADA

    Substitua os textos em maiúsculas pelos valores reais apresentados no GitHub.

    Confirme que está na pasta que contém o arquivo package.json antes de executar comandos npm run. Caso o template tenha uma pasta interna chamada case-auditoria-api, entre nela.

  3. Execute o diagnóstico de ambiente

    Terminal 
    npm run doctor

    Esse script verifica os requisitos do laboratório e informa o que precisa ser corrigido caso alguma ferramenta não esteja disponível.

    Se falhar: não pule diretamente para o setup. Corrija o requisito indicado ou procure orientação com a mensagem do erro.

  4. Prepare o ambiente pela primeira vez

    Terminal 
    npm run setup

    O script realiza a preparação do ambiente: verifica pré-requisitos, cria o .env local, instala dependências do npm, inicializa o PostgreSQL via Docker Compose, gera o Prisma Client, aplica migrations e carrega dados fictícios.

    Atenção: não precisa executar npm install antes. O setup já instala as dependências.

    Mensagem esperada ao terminar: AMBIENTE PREPARADO. Execute: npm run dev.

  5. Inicie a API

    Terminal 
    npm run dev

    Mantenha esse terminal aberto enquanto utilizar a aplicação.

    Abra no navegador: http://127.0.0.1:3000/health

    A resposta esperada é:

    Resposta JSON 
    {"status":"ok","environment":"laboratory"}

    Esse retorno confirma que o servidor HTTP está respondendo. Ele não comprova que todas as funcionalidades ou requisitos de segurança foram validados.

  6. Teste a compilação e o funcionamento básico

    Em outro terminal, aberto na mesma pasta do projeto, execute:

    Terminal 
    npm run build
npm run test:smoke

    O build compila o TypeScript. Os testes smoke verificam operações funcionais básicas, como o endpoint de saúde, a autenticação e a leitura de dados autorizados.

    Importante: os testes smoke não são uma auditoria de segurança e não identificam deliberadamente todos os problemas que deverão ser investigados na disciplina.

  7. Próximas execuções

    Depois da primeira configuração, você poderá utilizar:

    Terminal 
    npm run lab

    Esse comando auxilia a iniciar o banco, se necessário, e executar a API.

    Para parar o container de banco de dados sem excluir seu volume:

    Terminal 
    npm run db:stop

    Não execute comandos que removam volumes ou recriem o banco de forma destrutiva sem orientação. Se estiver trabalhando com outra pessoa, lembre-se de registrar mudanças e evidências no repositório da equipe.

Problemas frequentes

Esta seção é compartilhada por todos os sistemas operacionais. Abra o erro que mais se aproxima da mensagem do seu terminal.

node ou npm não é reconhecido

Sintoma: o terminal informa que node, npm ou um dos comandos não existe.

Causas possíveis: Node.js não foi instalado, instalação incompleta, terminal aberto antes da instalação ou variável PATH incorreta.

Como verificar: feche e reabra o terminal, execute node -v e npm -v novamente e confira a instalação pelo site oficial. No macOS/Linux, se utilizar um gerenciador de versões, confirme se ele está carregado no terminal atual.

Não faça: instalar pacotes globais aleatórios ou copiar arquivos executáveis de fontes desconhecidas para solucionar o PATH.

PowerShell bloqueia a execução de npm.ps1

Sintoma: mensagem semelhante a "running scripts is disabled on this system".

Orientação: esse comportamento está relacionado às políticas de execução do PowerShell, não necessariamente ao Node.js. Experimente abrir o Prompt de Comando (cmd) ou executar npm.cmd -v / npm.cmd run doctor no PowerShell. Em computadores administrados pela instituição, siga a política local. Evite alterar permanentemente as políticas de segurança apenas para executar o laboratório.

git não é reconhecido

Sintoma: comando git não encontrado.

Como resolver: confirme a instalação pelo site oficial, feche e reabra o terminal, execute git --version e verifique a integração do Git ao PATH. No macOS, as ferramentas de linha de comando podem resolver a ausência de Git.

docker compose não é reconhecido

Sintoma: docker funciona, mas docker compose version falha.

Causa possível: Compose plugin ausente ou instalação incompleta do Docker. Não confunda o comando moderno docker compose com a versão antiga docker-compose.

Como resolver: atualize ou instale o Docker Desktop, no Windows/macOS, ou o Compose plugin, no Linux, usando a documentação oficial. Depois abra novo terminal e repita o comando.

Cannot connect to the Docker daemon

Sintoma: docker info não consegue se comunicar com o Docker Engine.

Windows/macOS: abra o Docker Desktop e aguarde sua inicialização. Confira os requisitos da máquina e a virtualização.

Linux: confirme se o serviço está ativo com sudo systemctl status docker quando a distribuição utilizar systemd.

Importante: docker --version pode funcionar mesmo com o Engine parado. O diagnóstico relevante é docker info.

WSL 2 ou virtualização indisponível no Windows

Sintoma: o Docker Desktop não inicia e solicita WSL 2, virtualização ou recurso de sistema.

Como proceder: consulte os pré-requisitos oficiais do Docker Desktop. Uma instalação ou alteração de configuração pode exigir permissão de administrador e reinicialização. Se você utiliza computador corporativo/institucional, não contorne restrições de segurança. Utilize temporariamente a máquina de outro integrante da equipe e registre o impedimento.

permission denied ao usar Docker no Linux

Sintoma: seu usuário não consegue acessar o Docker daemon, mesmo com o serviço ativo.

Como proceder: consulte a documentação oficial de pós-instalação e verifique a política de permissões da máquina. O acesso ao grupo docker equivale a conceder privilégios importantes no sistema. Não utilize chmod 666 no socket Docker nem altere permissões indiscriminadamente.

GitHub retorna 404 no repositório da equipe

Sintoma: o link do repositório privado abre uma página 404 ou o clone indica ausência de acesso.

O que verificar: você está logado na conta GitHub correta? O convite para a organização foi aceito? Seu usuário foi associado ao Team certo? Sua equipe já recebeu permissão no repositório?

Como resolver: consulte o guia de acesso ao GitHub e, se necessário, informe seu username GitHub ao responsável pela disciplina. Não compartilhe sua senha ou token para obter acesso.

npm install / npm ci falha durante o setup

Sintoma: a instalação de dependências para com erro de conexão, permissão, pacote não encontrado ou incompatibilidade.

Como investigar: confira a versão do Node.js com node -v, sua conexão com a internet e a mensagem exata de erro. Se houver rede corporativa, proxy ou certificados institucionais, procure o suporte adequado; não desative verificações TLS para contornar o problema.

Se o erro indicar package-lock.json: confirme que está usando a pasta e o repositório corretos e que os arquivos do projeto estão íntegros. Não apague ou modifique o lockfile às cegas.

Falha ao iniciar PostgreSQL ou aplicar migrations

Sintoma: o setup falha ao iniciar container, conectar ao banco ou executar migrations do Prisma.

Como verificar:

Terminal 
docker compose ps
docker compose logs --tail=50

Confirme que o Engine está ativo, que o banco iniciou e que o arquivo .env está coerente com o compose.yaml. Não publique seu .env para pedir ajuda.

Porta do banco: a configuração do laboratório utiliza 55433 no computador. Se já estiver ocupada por outro processo, procure orientação antes de alterar a configuração do Docker e a string de conexão.

Porta 3000 já está em uso

Sintoma: a API não inicia e informa algo como EADDRINUSE.

Causa provável: outro processo já está usando a porta 3000, possivelmente outra execução da própria API.

Como resolver: verifique se existe outro terminal com npm run dev ativo e encerre apenas a execução que você reconhece. Se necessário, a configuração de porta pode ser ajustada no .env, mas nesse caso o endereço do /health também mudará.

/health não abre ou retorna erro

Sintoma: o navegador não abre http://127.0.0.1:3000/health.

O que verificar: o npm run dev está em execução? Houve erro no terminal? A aplicação está na porta 3000? Você está acessando o mesmo computador em que a API foi iniciada?

Importante: 127.0.0.1 significa o computador em que o navegador está rodando. Se você abrir o link no celular, ele não apontará automaticamente para a API do notebook. Não exponha a API vulnerável na rede para contornar essa situação.

Requisição recebe 401 ou token inválido

Sintoma: endpoints protegidos respondem com erro de autenticação.

Como verificar: faça login novamente utilizando a conta fictícia disponibilizada na documentação do projeto e inclua o token retornado no cabeçalho Authorization: Bearer SEU_TOKEN. Confira se o token pertence ao ambiente atual e não foi copiado com aspas ou espaços extras.

Cuidados: não cole tokens em páginas públicas, prints de suporte ou commits.

O computador não consegue executar Docker

Situação: restrições institucionais, limitações de hardware, ausência de virtualização ou falta de privilégios administrativos impedem a configuração local.

Plano alternativo: participe da investigação do código diretamente no repositório privado da equipe e trabalhe, quando possível, no computador de outro integrante. Registre o problema e procure orientação para os testes que dependem da API em execução.

O foco da disciplina é revisão de código e análise de segurança. A instalação local é um meio para trabalhar no projeto, não um critério de nota isolado.

Cuidados de segurança e encerramento

O projeto foi construído para estudo e contém vulnerabilidades intencionais. Por isso, mantenha a API restrita ao ambiente local e utilize somente os dados fictícios fornecidos.

  • Não publique o servidor em hospedagens externas ou na internet.
  • Não compartilhe .env, credenciais, tokens JWT ou informações pessoais.
  • Não utilize bases de dados reais ou de sistemas corporativos.
  • Não execute comandos destrutivos como remoção de volumes de banco sem orientação.
  • Não confunda testes smoke aprovados com comprovação de segurança da API.

Antes de começar a atividade prática

Confira se você consegue:

  • Identificar seu sistema operacional e acessar as instruções correspondentes.
  • Executar node -v, npm -v, git --version, docker compose version e docker info.
  • Acessar o repositório privado da equipe.
  • Executar npm run doctor e, se for a primeira instalação, npm run setup.
  • Iniciar a API e consultar o endpoint /health.
